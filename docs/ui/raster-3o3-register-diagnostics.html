raster-3o3 — the agreed register diagnostics and §9.1

The agreed outcome, in the words that ship. Every message, every label, and §9.1 in full. The options that were rejected, and why, are in the bead's plan under User-facing decisions.

§9.1, in full, as it would land

### 9.1 Named registers ppu.ctrl = $80 ppu.mask = $1E var s: u8 = ppu.status // read; clears vblank and the latch ppu.addr = $3F // high byte, then low ppu.addr = $00 ppu.data = $21 ppu.scroll = x ppu.oam_addr = 0 ppu.oam_data = $18 mmc3.bank_select = 6 mmc3.bank_data = 0 Named access exists so the compiler understands hardware side effects — write ordering, the `$2005`/`$2006` shared latch, `$2002` clearing that latch on read. The compiler warns when a sequence violates a known hardware requirement. **rasterc today:** every line above compiles. Three things this section once showed are intended and not built: `ppu.addr = $3F00`, one 16-bit write to the address latch, because `u16` values are not supported anywhere yet; OAM DMA through `$4014`, which stalls the CPU for 513 or 514 cycles and cannot be admitted until a timed block can charge it; and the APU registers, which today belong to the linked sound driver (§8.3).

Ten lines became eleven. Every one of them compiles — verified by building each. The three absent features are named with the reason each is absent, and the block is copy-pasteable.

The oam.dma naming, decided

Chosen: N-A — say the concept, not the spelling. §9.1 no longer shows oam.dma, and nothing in the project commits to that name over ppu.oam_dma. The message names the hardware feature and the reason, and matches §9.1's note word for word. Rejected: N-B, “oam.dma is not supported yet”, which would have promised a spelling in a terminal message that the spec had just stopped showing.

error: OAM DMA is not supported yet --> demo.raster:4:5 | 4 | oam.dma = $02 | ^^^^^^^ $4014 stalls the CPU for 513 or 514 cycles = note: this release compiles `main`, `fn`, `if`, `while`, `for`, u8 arithmetic, and `ppu.*` / `mmc3.*` register writes; timed blocks with `cycles`, `pad`, `sync exact` and `wait cycles`; and one `frame` of `every ... scanlines` events

Note that oam.addr and oam.data are still recognised by name — that is what makes “$2003 is spelled ppu.oam_addr” possible — so the oam namespace is known to the compiler as three names it does not have, and to the spec as none.
