raster-3o3 — the two lines nobody counted

I compiled §9.1's block line by line. The bead says three lines are broken. Five of the ten are. The two extra ones are not about register names at all, and “every line above compiles” cannot be written until they are decided.

### 9.1 Named registers ppu.ctrl = $80 // compiles ppu.mask = $1E // compiles ppu.status // read <-- DOES NOT COMPILE ppu.addr = $3F00 // <-- DOES NOT COMPILE ppu.data = $21 // compiles ppu.scroll = x // compiles oam.addr = 0 // <-- known, decided oam.dma = $02 // <-- known, decided apu.pulse1.volume = $BF // <-- known, decided mmc3.bank_select = 6 // compiles mmc3.bank_data = 0 // compiles

Line 3 — ppu.status on a line of its own

error: only direct calls and assignments are supported as statements --> demo.raster:2:5 | 2 | ppu.status | ^^^^^^^^^^ only direct calls and assignments are supported as statements

The spec's // read comment says what it is for: reading $2002 for its side effect — it clears the vblank flag and resets the $2005/$2006 latch, which is the very thing the paragraph under the block is about. A read whose value you throw away is a real NES idiom. rasterc has no way to write it. var s: u8 = ppu.status does compile today.

S-A Show the form that compiles
var s: u8 = ppu.status // read; clears vblank and the latch

True today, and teaches the side effect in the same line. Cost: the author is made to name a variable they do not want, and the language loses a form it should probably have.

S-B Keep the bare form; file a bead for it
ppu.status // read — not in this release

Keeps the idiom on the page as intended language. Cost: a second line in the block that does not compile, against the whole point of choosing spec option 1, and a new bead.

S-C Drop the line

§9.2 already shows var v: u8 = peek($2002), and §9.5 (raster-1t9) will list which registers read.

Smallest change. Cost: §9.1 stops showing a read at all, and the prose right beneath it is about what reading $2002 does.

Line 4 — ppu.addr = $3F00

error: integer literal overflows u8 --> demo.raster:2:20 | 2 | ppu.addr = $3F00 | ^^^^^ integer literal overflows u8

$2006 is a byte port. Hardware wants the high byte then the low byte, through the shared latch. The spec's single 16-bit write is a convenience the language does not have — u16 is refused everywhere today (annotation_is_u8, crates/raster-ir/src/lib.rs:1374).

P-A Show the two byte writes
ppu.addr = $3F // high byte, then low ppu.addr = $00

True today, and it is what the latch paragraph underneath is describing — the block finally demonstrates the thing the prose explains. Cost: two lines where the design wanted one, and the 16-bit convenience disappears from the spec.

P-B Keep the 16-bit form, name it in the note
ppu.addr = $3F00 // not in this release

Keeps the convenience as declared intent. Cost: a second non-compiling line in a block chosen to be copy-pasteable, and it silently commits the language to 16-bit stores to a byte port — a bigger promise than it looks.

P-C Both: two byte writes now, the convenience in the note
ppu.addr = $3F // high byte, then low ppu.addr = $00 **rasterc today:** ... `ppu.addr = $3F00`, one 16-bit write to the address latch, is intended and not built: `u16` values are not supported anywhere yet.

The block compiles and the intent survives. Cost: the longest note of the three.

And the message for the bare read, if it stays refused

Whatever §9.1 shows, someone will write ppu.status on its own line, because the spec has shown it since draft 0.1. Today they get a message about statements in general.

M-A Leave it
error: only direct calls and assignments are supported as statements | ^^^^^^^^^^ only direct calls and assignments are supported as statements

No new code. The author is told the rule and not the fix.

M-B Name the fix when the statement is a register read
error: a register read cannot stand on its own as a statement --> demo.raster:2:5 | 2 | ppu.status | ^^^^^^^^^^ assign it to a variable: `var s: u8 = ppu.status`

Every author who copies §9.1 lands here, and is moved on in one step. Cost: a special case in the statement checker for one shape of expression.
