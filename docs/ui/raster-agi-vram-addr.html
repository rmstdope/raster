vram_addr — setting a PPU address in one line

Agreed so far: a convenience name vram_addr beside backdrop (§9.3) takes the whole 16-bit address and expands to the two $2006 writes, high then low, back to back with nothing between them. Always plain writes and always 12 cycles, with no scroll handling. ppu.addr stays the raw byte port, unchanged.

The happy path

vram_addr = $3F00 // palette ppu.data = $0F vram_addr = $2000 + 32*4 + 2 // a constant expression is fine

What lands in the ROM

LDA #$3F STA $2006 LDA #$00 STA $2006 ; 12 cycles, counted in any timed block like any other write

State — above $3FFF (error)

error: $4000 is outside the PPU address space --> demo.raster:12:13 | 12 | vram_addr = $4000 | ^^^^^ PPU addresses run $0000 to $3FFF | = note: the PPU ignores the top two bits, so this would set $0000

State — a variable (16-bit values are not in this release)

error: vram_addr needs a constant address in this release --> demo.raster:12:13 | 12 | vram_addr = row | ^^^ `row` is a variable | = help: to set an address from a variable, write the two bytes to ppu.addr, high byte first

State — a 16-bit number on the raw port

WORDING 1 — CHOSEN
error: ppu.addr is written one byte at a time --> demo.raster:12:12 | 12 | ppu.addr = $3F00 | ^^^^^ $3F00 does not fit in a byte | = help: to set the whole address in one line, write `vram_addr = $3F00`
WORDING 2 — rejected
error: $3F00 is too big for ppu.addr, which takes one byte --> demo.raster:12:12 | 12 | ppu.addr = $3F00 | ^^^^^ use vram_addr for a whole address | = help: `vram_addr = $3F00`

State — a short number, e.g. vram_addr = $3F

OPTION 1 — CHOSEN — silent: it sets $003F
$0000–$00FF is the start of pattern table 0, which is a real place to write CHR RAM. Nothing is printed.
OPTION 2 — rejected — warn
warning: vram_addr = $3F sets address $003F --> demo.raster:12:13 | 12 | vram_addr = $3F | ^^^ did you mean $3F00? write $003F to keep this and silence the warning

Cost: anyone writing CHR RAM at the bottom of the address space has to write leading zeros.

State — something between two raw ppu.addr writes

Unchanged: today's warning stays. With vram_addr this can't happen.

What the spec says

§9.1 example

ppu.addr = $3F // high byte, then low ppu.addr = $00
Unchanged. The "rasterc today" note that promises ppu.addr = $3F00 is removed.

§9.3 (added)

vram_addr = $3F00 // the $2006 pair, high byte then low
vram_addr is a virtual register. Assigning a constant address to it compiles to the two $2006 writes, high byte first, with nothing in between, so nothing can reset the latch halfway. It costs 12 cycles wherever it is. It does not restore the scroll: written while the screen is drawing, it moves the scroll, just like the raw pair does. Addresses run $0000 to $3FFF.
