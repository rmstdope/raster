The build summary, telling the author which bytes are theirs

Agreed with the navigator while planning raster-7nl. Every figure below is from a real build of main at b085e06, not an illustration: the reset runtime is 132 bytes — a 131-byte reset prologue at the front of the fixed bank and the interrupt handler’s one-byte RTI at the back — and it is the same 132 in every program this compiler builds.

01 · The demo

examples/mvp/demo.raster, five statements. The two new rows sit directly under fixed, which is the row they elaborate; entry, cycles and warnings keep their order below them.

$ rasterc examples/mvp/demo.raster Compiled examples/mvp/demo.raster -> examples/mvp/demo.nes mapper MMC3 (4), NTSC prg 32 KiB, 4 banks of 8 KiB chr 8 KiB RAM fixed $E000-$FFFF, 160 of 8186 bytes used yours 28 bytes runtime 132 bytes, the reset sequence around your program entry reset $E000, nmi $E09F, irq $E09F

One number per row, like every other row in the block, so yours can be compared across two builds without reading a sentence. runtime carries a clause because its figure is the one the author cannot work out from the number; yours needs none.

02 · An empty main

Source: main { } and nothing else. Three bytes are the halt loop rasterc puts at the end of every main so the console has somewhere to sit. They count as the author’s: the line is drawn at the linker, so everything wrapped around the generated program is the runtime and everything the compiler made from the source is yours. Three is therefore the floor — yours is never 0 and never 1.

$ rasterc empty.raster fixed $E000-$FFFF, 135 of 8186 bytes used yours 3 bytes runtime 132 bytes, the reset sequence around your program entry reset $E000, nmi $E086, irq $E086

03 · A function, a loop, and a cycles(?) region

Four digits, and the rows below the split unchanged.

$ rasterc big.raster fixed $E000-$FFFF, 221 of 8186 bytes used yours 89 bytes runtime 132 bytes, the reset sequence around your program entry reset $E000, nmi $E0DC, irq $E0DC cycles hblank: 15 cycles

04 · One byte from full

$ rasterc edge.raster fixed $E000-$FFFF, 8185 of 8186 bytes used yours 8053 bytes runtime 132 bytes, the reset sequence around your program entry reset $E000, nmi $FFF8, irq $FFF8

05 · And when it does not fit

The refusal quotes the same conflated figure, so it gets the split too — turned into the action, because at this moment the author does not want to know how the bytes divide, they want to know how many of their own have to go. The new note is second of the three, after the sizes it does arithmetic on and before the standing explanation about bank switching.

$ rasterc huge.raster error: the program does not fit the MMC3 fixed bank = note: 8631 bytes of code, and $E000-$FFFF holds 8186 = note: 132 of those are the reset runtime, so 445 bytes of your own have to go = note: PRG bank switching is not supported yet, so all code lives in the fixed bank error: could not compile huge.raster (1 error)

What was rejected, and why

A continuation line under fixed, with no label. It kept one fact in one place, but it would have been the only label-less row in the block, so it could not be found by scanning the label column and read as wrapped text.

A parenthetical on the fixed row — 160 of 8186 bytes used (132 the reset runtime). The summary would not have grown at all, but the author’s own number is never printed: they would subtract 132 from 160 themselves, every build, and it is their number this exists to give them.

A single row carrying both figures, such as yours  28 bytes; the reset runtime is the other 132. One line rather than two, but the value column then holds a sentence where every other row holds a value.

Counting the halt loop as the compiler’s, so an empty main reads yours  0 bytes. Truer for that one program, but codegen would have to judge which of its own bytes were the author’s — and the halt label doubles as the top of the frame loop once a program has a frame block, so the judgement would be wrong again the first time a construct is added.

Leaving the overflow error alone. 132 bytes is a rounding error against a 445-byte overshoot, and every note is a line between the author and the next one — but the note that says how many bytes have to go is the one that ends the run-fix-run treadmill, and it is only correct once the runtime is subtracted.

A longer clause on the runtime row — the reset sequence rasterc wraps every program in, at 71 columns the widest row in the block after the paths. The chosen clause says the same in 57.
