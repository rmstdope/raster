Option C — warn only when the compiler can see the reset map undone

Same new warning severity as Option B, but a narrower trigger. Repointing a bank window is what the bank registers are for and stays silent. What warns is the part an author almost never means: bits 6 and 7 of a bank select — PRG mode and CHR A12 inversion — which reinterpret every bank register at once, and a bank-select value the compiler cannot see through.

1 · Bit 7 set: the pattern tables swap, and it says so

mmc3.bank_select = $80 mmc3.bank_data = $01
$ rasterc demo.raster warning: this bank select changes the MMC3 mapping mode --> demo.raster:5:5 | 5 | mmc3.bank_select = $80 | ^^^^^^^^^^^^^^^^^^^^^^ bit 7 swaps the two pattern tables from here on = note: reset chose CHR A12 inversion off, so pattern table 0 is at PPU $0000; clearing bit 7 keeps that map = note: bits 6 and 7 take effect from whichever bank select was written last, not from the bank data that follows Compiled demo.raster -> demo.nes mapper MMC3 (4), NTSC prg 32 KiB, 4 banks of 8 KiB chr 8 KiB RAM fixed $E000-$FFFF, 214 of 8186 bytes used entry reset $E000, nmi $E0D5, irq $E0D5 warnings 1

2 · The intended CHR animation is silent

Bits 6 and 7 clear, so the mode reset chose still holds; the author is repointing one window, which is the ordinary use of these registers.

mmc3.bank_select = 0 mmc3.bank_data = tile
$ rasterc anim.raster Compiled anim.raster -> anim.nes mapper MMC3 (4), NTSC prg 32 KiB, 4 banks of 8 KiB chr 8 KiB RAM fixed $E000-$FFFF, 198 of 8186 bytes used entry reset $E000, nmi $E0C5, irq $E0C5

3 · Bit 6 set: PRG mode 1, and the $8000 window moves

mmc3.bank_select = $46
$ rasterc prg.raster warning: this bank select changes the MMC3 mapping mode --> prg.raster:5:5 | 5 | mmc3.bank_select = $46 | ^^^^^^^^^^^^^^^^^^^^^^ bit 6 moves the fixed PRG bank from $C000 to $8000 = note: reset chose PRG mode 0, a linear 32 KiB map with this code in the fixed bank at $E000; clearing bit 6 keeps that map = note: bits 6 and 7 take effect from whichever bank select was written last, not from the bank data that follows Compiled prg.raster -> prg.nes ... warnings 1

4 · A value the compiler cannot see through

Neither bit can be ruled out, so it warns — with a different label, because the author has done nothing wrong and the point is that rasterc cannot check it.

mmc3.bank_select = which
$ rasterc dynamic.raster warning: rasterc cannot tell whether this bank select changes the mapping mode --> dynamic.raster:7:5 | 7 | mmc3.bank_select = which | ^^^^^^^^^^^^^^^^^^^^^^^^ this value is not a constant, so bits 6 and 7 are unknown here = note: bit 6 is PRG mode and bit 7 is CHR A12 inversion; keeping both clear keeps the map reset chose Compiled dynamic.raster -> dynamic.nes ... warnings 1

5 · No bank write, or only bank data: nothing changes

6 · A program that also fails to compile

$ rasterc broken.raster warning: this bank select changes the MMC3 mapping mode --> broken.raster:5:5 | 5 | mmc3.bank_select = $80 | ^^^^^^^^^^^^^^^^^^^^^^ bit 7 swaps the two pattern tables from here on = note: reset chose CHR A12 inversion off, so pattern table 0 is at PPU $0000; clearing bit 7 keeps that map = note: bits 6 and 7 take effect from whichever bank select was written last, not from the bank data that follows error: `loop` is not supported yet --> broken.raster:8:5 | 8 | loop {} | ^^^^^^^ `loop` is not supported yet = note: this release compiles `main`, `fn`, `if`, `while`, `for`, u8 arithmetic and `ppu.*` / `mmc3.*` register writes error: could not compile broken.raster (1 error, 1 warning)

What this costs. Two warning texts instead of one, a constant-fold at the assignment, and a rule an author has to read twice to hold in their head. It is also silent about the write that repoints R6 or R7 and moves the $8000 window under a program that assumed a linear map. What it buys. Every warning it prints names a specific thing that just became untrue, and the correct CHR animation of case 2 — the whole point of these registers — builds without a word.
