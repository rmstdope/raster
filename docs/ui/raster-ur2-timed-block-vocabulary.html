The timed-block vocabulary, finished

Every place the spec still says region for a cycles block now says block or timed block — the same word the compiler's own messages already use. Six edits in §6.3–§6.5, plus §6.6's marker becomes stricter.

01 §6.3 — the paragraph under the heading

rasterc costs a regiona block by adding up its instructions, so anything whose generated code can move the program counter elsewhere is refused.

02 §6.3 — rule 5, the "rasterc today" column

as designed for IRQ — the php/sei … plp bracket costs nine cycles and is charged to the region'sblock's own budget, so the annotation is the region'sblock's wall-clock cost while no NMI lands inside it. …

03 §6.3 — rule 6, the designed column

6. A regiontimed block must be straight-line. Generated code that can go anywhere but the next instruction … is a compile error whatever construct produced it.

04 §6.4 — missed last time because it wraps across two lines

Raster's position is that inside a timed regiontimed block, "I cannot prove this" must be a compile error and not a shrug.

05 §6.5 — "rasterc today" note

… widen the budget and let pad fill it instead. Outside a regiona timed block, wait cycles(N) is built for any N ≥ 2; …

06 §6.6 — "rasterc today" note

rasterc today: as designed, and enforced — a timed block that writes a PPU register with no preceding sync exact is refused. A frame handler is entered already synchronized and needs none of its own.

rasterc today: stricter — a timed block that writes a PPU register is refused unless a sync exact comes earlier in the same list of statements, whether or not the screen is rendering; one further out does not count. A frame handler is entered already synchronized and needs none of its own.

Uses the spec's own definition: stricter the compiler refuses more than the text allows. The designed text asks for sync exact only during rendering; the compiler asks for it always.
