AGREED · THE RULE

Reading a write-only register is an error

Thirteen of rasterc's sixteen named registers are write-only ports. A read of one does not return the last value written — a PPU port returns whatever was last on the PPU's data bus, and an MMC3 port returns a byte of the author's own program from the PRG bank mapped there. There is no right-hand side that makes such a read correct, so rasterc refuses it and says what to write instead.

1 · A compound assignment — the read is not in the source

+= reads its destination before it writes, so this line reads $8000 without the author ever having asked for a read. That is why this case gets a note the others do not.

main { mmc3.bank_select += $80 }
error: `mmc3.bank_select` cannot be read --> demo.raster:2:5 | 2 | mmc3.bank_select += $80 | ^^^^^^^^^^^^^^^^ $8000 is a write-only port = note: `+=` reads its destination before it writes, so this reads $8000 = note: reading $8000 returns a byte of your own program from the PRG bank mapped there, not the last value written = note: keep what you wrote in a variable of your own and write the whole value error: could not compile demo.raster (1 error)

The carets cover the destination only, not the whole statement: the label names the port, and $80 is not part of the port.

2 · A read the author did write

main { var m: u8 = ppu.mask }
error: `ppu.mask` cannot be read --> demo.raster:2:17 | 2 | var m: u8 = ppu.mask | ^^^^^^^^ $2001 is a write-only port = note: reading $2001 returns whatever was last on the PPU's data bus, not the last value written = note: keep what you wrote in a variable of your own and write the whole value

3 · Two reads on one line are two errors

main { ppu.ctrl = ppu.mask | ppu.scroll }
error: `ppu.mask` cannot be read --> demo.raster:2:16 | 2 | ppu.ctrl = ppu.mask | ppu.scroll | ^^^^^^^^ $2001 is a write-only port = note: reading $2001 returns whatever was last on the PPU's data bus, not the last value written = note: keep what you wrote in a variable of your own and write the whole value error: `ppu.scroll` cannot be read --> demo.raster:2:27 | 2 | ppu.ctrl = ppu.mask | ppu.scroll | ^^^^^^^^^^ $2005 is a write-only port = note: reading $2005 returns whatever was last on the PPU's data bus, not the last value written = note: keep what you wrote in a variable of your own and write the whole value error: could not compile demo.raster (2 errors)

One error per read, the way every other stage reports every fault it can see — so a file is one read rather than a run-fix-run treadmill.

4 · The error suppresses the bank-select warning on the same line

mmc3.bank_select += $80 would also trip the mapping-mode warning, whose “cannot tell” arm fires on any value rasterc cannot fold. It does not fire here: the statement is being rewritten, so what its value would have been is moot, and one fault gets one message. Section 1 above is the whole of what this source prints.

5 · A register that reads is untouched

main { ppu.addr = $3f ppu.addr = $00 var entry: u8 = ppu.data }
Compiled demo.raster -> demo.nes mapper MMC3 (4), NTSC prg 32 KiB, 4 banks of 8 KiB chr 8 KiB RAM

ppu.data's read is buffered — it returns the previous byte — and reading ppu.status clears the vblank flag and the $2005/$2006 latch. Both are real hazards and both have their own beads; neither is this one, which is only about ports that do not read at all.

Thirteen refused, three allowed. Writes are unaffected: every one of the sixteen may still be written, and this bead changes nothing about a write.

7 · What was rejected

Warn instead of refusing. Reuses the machinery raster-6jr shipped and never blocks an author — but there is nothing here the author could know that rasterc does not, so a warning would let an always-wrong program become a ROM.

Say nothing; document it only. No false positives ever — but spec §9.1 already promises the compiler warns when a sequence violates a known hardware requirement, and a documented trap the compiler can see and does not mention fails silently, in a ROM, on someone else's hardware.

Catch only the compound assignment. Matches the original report and is one hook instead of two — but ppu.ctrl = ppu.mask | $80 reads the same dead port and looks like ordinary read-modify-write code, which makes it the more insidious of the two.

Refuse writing ppu.status in the same bead. The mirror-image bug, and nearly free — but it widens a bead that already grew from += to every read, and the write side gets its own interview.
