raster-6y8 — the agreed OAM DMA design

The agreed outcome, in the words that ship. Every message, every note, and the two spec edits. The options that were rejected, and why, are in the bead's plan under User-facing decisions.

The name

$4014 is ppu.oam_dma: the seventeenth named register, write-only, joining the eight ppu.* names rather than opening an oam or dma namespace of its own.

main { ppu.oam_addr = 0 ppu.oam_dma = $02 // copy $0200-$02FF into sprite memory }

Outside a timed block this is one STA $4014 and nothing else. The compiler charges nothing, measures nothing and warns about nothing.

Inside a timed block: charged 514, admitted anywhere

The stall is 513 cycles, or 514 when the write lands on an odd CPU cycle, and rasterc cannot know the parity: it counts from the top of a block, never from reset. So the block is charged 514 — the worst case, which is the direction that never overruns, exactly as an indexed read that may cross a page is charged its extra cycle today.

sync exact cycles(600) pad { ppu.oam_dma = $02 // 514 stall + 4 store + 9 masking, padded to 600 }

The warning, on an exact budget only

A block padded to exactly 600 spends 599 or 600, and this is the first place a Raster budget stops being exact. cycles(<= N) and cycles(?) stay silent: a ceiling is still a true ceiling, and a report is explicitly a measurement.

warning: this block's cost is one cycle uncertain --> demo.raster:3:5 | 3 | cycles(600) pad { | ^^^^^^^^^^^ an OAM DMA stalls 513 or 514 cycles, so this block spends 599 or 600 = note: the block is charged the worst case, so it never overruns; `cycles(<= 600)` says the same thing without the promise

With more than one in the same block:

| ^^^^^^^^^^^^ 2 OAM DMAs stall 513 or 514 cycles each, so this block spends between 1198 and 1200

When the stall is what blew the budget

A second note, printed only when the block holds a DMA. It names the ratio, so the arithmetic is done: “514 of 527” says at a glance that the stall is the block.

error: timed block exceeds its budget --> demo.raster:3:5 | 3 | cycles(114) pad { | ^^^^^^^^^^^ block costs 527 cycles, budget is 114 = note: an indexed read that may cross a page and a branch that may be taken are both charged their worst case = note: 514 of this block's 527 cycles are one OAM DMA, charged the worst of the 513 or 514 it may stall

With more than one:

= note: 1028 of this block's 1240 cycles are 2 OAM DMAs, charged the worst of the 513 or 514 each may stall

A frame handler gets this error and no other: a handler's budget is one scanline — 114 cycles — and the stall is more than four times that, so a DMA in a handler is refused by the budget check that already exists.

Reading it

$4014 is write-only, so raster-1t9's refusal covers it — but its second note is chosen by address, and the rule is $8000 and above is the mapper, otherwise the PPU. $4014 is neither, and gets a third arm of its own rather than the false sentence about the PPU's data bus.

error: `ppu.oam_dma` cannot be read --> demo.raster:2:17 | 2 | var v: u8 = ppu.oam_dma | ^^^^^^^^^^^ $4014 is a write-only port = note: $4014 does not read back at all: it is a write-only trigger on the CPU bus, and a read of it returns whatever was last on that bus = note: keep what you wrote in a variable of your own and write the whole value

And the read a compound assignment makes for you, which is refused the same way with the operator named first:

error: `ppu.oam_dma` cannot be read | ^^^^^^^^^^^ $4014 is a write-only port = note: `+=` reads its destination before it writes, so this reads $4014 = note: $4014 does not read back at all: it is a write-only trigger on the CPU bus, and a read of it returns whatever was last on that bus = note: keep what you wrote in a variable of your own and write the whole value

sync exact applies to it, and that is deliberate

Naming it ppu.* means the existing rule matches it with no code written, and it is kept: a DMA writes the PPU's sprite memory, and a block that starts one is a block whose position in the frame matters.

error: `sync exact` is required before a timed block that writes a PPU register, because NMI entry is not cycle-exact --> demo.raster:3:5 | 3 | cycles(600) pad { | ^^^^^^^^^^^ `sync exact` is required before a timed block that writes a PPU register, because NMI entry is not cycle-exact

The spec

§9.5 — a row, and two numbers

Sixteen Seventeen registers have names. Three of them can be read, and fifteen sixteen of them can be written; `ppu.status` is the only one that can be read and not written. | `ppu.data` | `$2007` | **allowed, and buffered** | **allowed** | | `ppu.oam_dma` | `$4014` | refused | **allowed** | | `mmc3.bank_select` | `$8000` | refused | **allowed** |

The paragraph beneath the table explains a write-only read as either the PPU's data bus or a byte of your own program from the mapped PRG bank. $4014 is a third case and the paragraph says so.

§9.1 — the line, and the note
