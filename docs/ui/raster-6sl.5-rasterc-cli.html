What M4 ships

The command-line surface rasterc presents once milestone 4 lands, as agreed with the navigator. Every string on this page ships verbatim.

01 Why the demo writes the PPU address twice at the end

I ran the existing M1 ROM through the headless emulator. It does not show blue. It shows grey, and it shows grey whatever colour the source writes — $12, $21 and $0F all render identically. These are the real pixel values, not an illustration:

M1 today. rgb(83,83,83)
— and the same for every colour
With the fix. rgb(53,51,228)
— NES colour $12
With the fix. rgb(92,160,255)
— NES colour $21

Why. With rendering disabled and the PPU address sitting inside $3F00-$3FFF, the PPU puts out the palette entry the address points at rather than the backdrop. Writing $3F00 leaves the address at $3F01, which is zero, which is grey. Pointing the address back out of palette space fixes it.

Who does it. Two ppu.addr = $00 writes, and they belong to the author rather than the compiler. In a language whose whole claim is that you can count the cycles, a compiler that inserts PPU writes you did not write is a compiler you cannot count.

02 examples/mvp/demo.raster, corrected

// The whole of milestone 4: a backdrop colour, from source.
//
// rasterc emits the reset sequence, the two-vblank wait and the
// MMC3 bank layout around this. What is below is only your part.

const BACKDROP: u8 = $12        // NES colour $12, a mid blue

main {
    ppu.addr = $3f              // the palette lives at $3F00 ...
    ppu.addr = $00              // ... and $3F00 is the backdrop
    ppu.data = BACKDROP

    ppu.addr = $00              // leave palette space, or the screen
    ppu.addr = $00              // shows $3F01 instead of the backdrop
}

Two rules the note obeys. It says what the release can build, so it belongs beside a construct the release does not have at all — and it is said once per run, beside the first of them, because twice is noise and never leaves “yet” unexplained.

04 Failure text

Four errors an ordinary user can reach, with their notes.

// a file with no main block
error: this program has no `main` block
  = note: add `main { ... }` to give the ROM somewhere to start

// more code than the fixed bank holds
error: the program does not fit the MMC3 fixed bank
  = note: 8402 bytes of code, and $E000-$FFFF holds 8186
  = note: PRG bank switching is not supported yet, so all code lives
          in the fixed bank

// a while body longer than a branch can reach
error: a branch is too far for the 6502
  = note: the branch at $E4A0 must reach $E540, and 6502 branches reach
          127 bytes forward or 128 back

// more than 240 variables

05 Which refusals carry a note

Agreed for bead raster-fu0. A refusal earns the “this release compiles…” note when it names a construct the specification defines and this release does not compile anywhere — not when its wording happens to end in a particular phrase. Six constructs gain it: wait vblank, strings, characters, bool, function timing specifications, and storage classes other than in zp.

// a construct this release does not have
error: only `wait cycles` is supported yet; frame waits arrive with frame scheduling
 --> demo.raster:8:5
  |
8 |     wait vblank
  |     ^^^^^^^^^^^ only `wait cycles` is supported yet; frame waits arrive with frame scheduling
  = note: this release compiles `main`, `fn`, `if`, `while`, `for`, u8
          arithmetic and `ppu.*` / `mmc3.*` register writes

A construct that is fine in general and cannot be used inside a timed region is a different refusal, and gets a note of its own. Five of these: branch arms, a for loop, wait cycles, * / % and shifts, and a call. Said once per run, like the other.

// a construct the region's cost model cannot charge
error: a shift inside a timed region compiles to a loop whose cost is not yet proven
 --> shift.raster:4:23
  |
4 |         level = level >> 1
  |                       ^^ a shift inside a timed region compiles to a loop whose cost is not yet proven
  = note: a timed region is costed as straight-line code; loops and calls
          will be admitted once their cost can be measured

Everything else — a mistake in the program, and the catch-all arms that name no construct — carries neither note. Each of those already says what to do instead, and a list of supported constructs beside it would be noise.
