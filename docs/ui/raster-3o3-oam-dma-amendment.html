raster-3o3 — amended after sprite DMA was built (2026-10-29)

Both parts chosen: option A in each. Everything else in raster-3o3-register-diagnostics.html stands.

Option A — oam.dma is a wrong spelling, like oam.addr

Sprite DMA is built now, as ppu.oam_dma. Someone who writes the old spelling is told the right one, in exactly the shape oam.addr and oam.data already get. No "this release compiles…" note: nothing is missing, only misspelled.

Unchanged edges

One error per line, source order; no ROM written. A variable of your own called oam is never told "there is no oam namespace" — it gets the agreed "is a variable, not a register namespace" error. oam.foo (not one of the three) gets the general "there is no `oam` namespace / rasterc has ppu and mmc3".

Cost: none beyond the two cases already built this way. One rule for all three: the old oam.* names point at their ppu.* spelling.

Option A — twelve lines: sprite DMA added

The eleven agreed lines stay, and ppu.oam_dma = $02 joins them after the other two sprite-memory lines. Every port rasterc has a name for in the PPU group is shown once.

§9.1, as it would land

### 9.1 Named registers ppu.ctrl = $80 ppu.mask = $1E var s: u8 = ppu.status // read; clears vblank and the latch ppu.addr = $3F // high byte, then low ppu.addr = $00 ppu.data = $21 ppu.scroll = x ppu.oam_addr = 0 ppu.oam_data = $18 ppu.oam_dma = $02 // copies $0200-$02FF to sprite memory mmc3.bank_select = 6 mmc3.bank_data = 0 Named access exists so the compiler understands hardware side effects — write ordering, the `$2005`/`$2006` shared latch, `$2002` clearing that latch on read. The compiler warns when a sequence violates a known hardware requirement. rasterc today: every line above compiles. Two things this section once showed are intended and not built: `ppu.addr = $3F00`, one 16-bit write to the address latch, because `u16` values are not supported anywhere yet; and the APU registers, which today belong to the linked sound driver (§8.3).

What changed in the "rasterc today" note

Same note as agreed, with sprite DMA taken out because it is built: "Three things" becomes "Two things", and the clause "OAM DMA through `$4014`, which stalls the CPU for 513 or 514 cycles and cannot be admitted until a timed block can charge it;" is gone. ppu.addr = $3F00 stays exactly as agreed — two byte writes in the example, and the note naming 16-bit values as not built (main still refuses $3F00 as too big for a byte).

Every line compiles with no warning — checked against today's compiler, including ppu.oam_dma = $02 outside a timed block.

Cost: one line longer than agreed; the comment is new words, and it is the only line that needs one, since a write of $02 does not explain itself.
