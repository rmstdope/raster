BARE WRITE-ONLY REGISTER

raster-3o3 — a write-only register alone on a line (agreed)

A bare register on its own line is a read, so it gets the very same refusal the compiler already gives for var x: u8 = mmc3.irq_disable — same message, same label, same notes — with two extra notes: first why this counts as a read (the same pattern as the agreed note for +=), last the likely slip.

A write-only register on its own line (13 registers)

error: `mmc3.irq_disable` cannot be read --> demo.raster:2:5 | 2 | mmc3.irq_disable | ^^^^^^^^^^^^^^^^ $E000 is a write-only port = note: a register on a line by itself is read, so this reads $E000 = note: reading $E000 returns a byte of your own program from the PRG bank mapped there, not the last value written = note: keep what you wrote in a variable of your own and write the whole value = note: to write it, give it a value: `mmc3.irq_disable = <value>`

Cost: two new note lines. Everything above it is wording already shipped, so a write-only port gets one refusal wherever the read happens.

The same thing on a PPU port

error: `ppu.ctrl` cannot be read --> demo.raster:2:5 | 2 | ppu.ctrl | ^^^^^^^^ $2000 is a write-only port = note: a register on a line by itself is read, so this reads $2000 = note: reading $2000 returns whatever was last on the PPU's data bus, not the last value written = note: keep what you wrote in a variable of your own and write the whole value = note: to write it, give it a value: `ppu.ctrl = <value>`

Unchanged in every option — a register that can be read

error: a register read cannot stand on its own as a statement --> demo.raster:2:5 | 2 | ppu.status | ^^^^^^^^^^ assign it to a variable: `var s: u8 = ppu.status`

Same for ppu.oam_data and ppu.data, the only three that can be read.
