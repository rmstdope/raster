raster-eb4 — naming the bank register a call left selected

Agreed: a bank data write after a call that leaves R6 or R7 selected gets the definite warning, with a second dashed marker on the call (option B). A call that leaves R0–R5 selected is silent. A call whose function can leave different registers selected keeps the soft headline but marks the call and moves the advice after it (option D).

1 · Definite — the call leaves R6 selected

OPTION B — SAME WARNING, PLUS A SECOND MARKER ON THE CALL (recommended)
fn tick() { mmc3.bank_select = 6 } main { mmc3.bank_select = 0 tick() mmc3.bank_data = 4 }
warning: this write repoints the PRG window at $8000 --> demo.raster:6:5 | 5 | tick() | ------ this call leaves R6 selected 6 | mmc3.bank_data = 4 | ^^^^^^^^^^^^^^^^^^ R6 is selected, so this replaces $8000-$9FFF = note: reset chose a linear 32 KiB map with R6 = 0 and R7 = 1; the bytes at $8000 are not the ones it mapped from here on = note: PRG bank switching is not supported yet: banks 0 to 2 hold $FF, and bank 3 is a second view of the fixed bank at $E000

The compiler-standard secondary marker (as Rust and Clang draw them): the write is still the place the warning points, and the call that changed the selection is underlined in a second style above it. Cost: one more labelled line, and the marker uses a dashed underline as well as colour so it reads without colour.

When the call leaves R0–R5 selected

fn tick() { mmc3.bank_select = 2 } main { tick() mmc3.bank_data = 4 }

Silent — exactly as if mmc3.bank_select = 2 were written in place of the call. Today this gets the soft “cannot tell” warning.

Nested and distant calls

fn inner() { mmc3.bank_select = 7 } fn tick() { inner() } main { tick() var n: u8 = 3 mmc3.bank_data = n }
warning: this write repoints the PRG window at $A000 --> demo.raster:7:5 | 5 | tick() | ------ this call leaves R7 selected 6 | var n: u8 = 3 7 | mmc3.bank_data = n | ^^^^^^^^^^^^^^^^^^ R7 is selected, so this replaces $A000-$BFFF = note: reset chose a linear 32 KiB map with R6 = 0 and R7 = 1; the bytes at $A000 are not the ones it mapped from here on = note: PRG bank switching is not supported yet: banks 0 to 2 hold $FF, and bank 3 is a second view of the fixed bank at $E000

The marker sits on the call in the body being checked, however deep the select is. Lines between the call and the write are shown as usual (or elided the usual way when far apart).

2 · Unsure — the call can leave any register selected

OPTION D — SOFT WARNING THAT POINTS AT THE CALL (recommended)
fn tick(fast: bool) { if fast { mmc3.bank_select = 6 } else { mmc3.bank_select = 1 } } main { tick(true) mmc3.bank_data = 4 }
warning: rasterc cannot tell which bank register this write lands on --> demo.raster:7:5 | 6 | tick(true) | ---------- this call can leave any register selected 7 | mmc3.bank_data = 4 | ^^^^^^^^^^^^^^^^^^ rasterc cannot see which register this call leaves selected = note: R6 and R7 are the two 8 KiB PRG windows; a write landing on either one repoints $8000 or $A000 = note: selecting with a literal 0 to 5 after the call, before the write, keeps the map reset chose

Same headline as today, but the call is marked the same way as in option B, and the advice says where the fix goes. Cost: three changed lines for a case that is already understood once you look.
