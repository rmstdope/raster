raster-72o — NMI and a cycles block outside a frame

Agreed with the navigator over two rounds. A cycles block in main is charged nothing for an NMI that can land inside it; the sei bracket does not mask NMI. What ships is a warning — the ROM is still written — and a corrected rule 5 in the specification. Every terminal block below is the layout rasterc prints.

1 · The program that compiles silently today

1  main {
2      ppu.ctrl = $88          // NMI on
3      sync exact
4      cycles(114) pad {
5          ppu.mask = $1e
6      }
7  }

The php/sei … plp bracket masks IRQ, not NMI. One NMI inside the block costs it 13 cycles (7 to enter, 6 for the runtime’s bare RTI), so the 114 it asserts is false.

Decided: warn, and still build — the same severity as the timed-frame NMI warning. Rejected: refusing.

Two first notes, because the two causes are fixed differently. “Some paths and not others” means the paths disagree about bit 7; two paths that both leave it clear are silent.

7 · The language reference, rule 5 of §6.3

Today:

| **5. No interrupts, unless declared.** ... | **as designed** — the `php`/`sei` …
`plp` bracket costs nine cycles and is charged to the region's own budget, so
the annotation is the region's wall-clock cost. |

After (the “rasterc today” cell; the designed cell is unchanged):

| **5. No interrupts, unless declared.** ... | **as designed for IRQ** — the
`php`/`sei` … `plp` bracket costs nine cycles and is charged to the region's own
budget, so the annotation is the region's wall-clock cost while no NMI lands
inside it. The I flag cannot mask NMI: rasterc warns when NMI can be on as a
block in `main` starts, and says so when it cannot tell. A block in a `using
irq` handler is not warned, since the handler runs on visible scanlines and NMI
does not; a `using timed` frame is warned as a whole (section 7.1). |
